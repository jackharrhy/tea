# @tea/gurgur

Gurgur's authoritative Bun world, WebRTC transport, saved SQLite state and WebGPU browser. Remix 3 renders the page in `app/` and mounts the original Three renderer through a client component with abortable cleanup. `server/src/index.ts` is the Bun entry, `web/src` owns browser gameplay, `content/` contains the authored and compiled map and media, and `tools/` contains the map compiler and diagnostic harnesses.

Install at the Tea root with `npm ci` and use Bun 1.4.4. `npm run check --workspace @tea/gurgur` typechecks, runs functional and isolated host-budget tests, and builds the app; the two shared packages have independent checks. Set `DATABASE_PATH` to a new local SQLite path, `PORT` to a free port, and run `npm run dev --workspace @tea/gurgur`. The server defaults to port 3000. Production requires `ADMIN_TOKEN` of at least 16 characters and a matching `PUBLIC_ORIGIN`; WebRTC UDP uses ports 40000–40100 by default. `docker compose --profile gurgur up --build gurgur` is a local, opt-in container launch and requires `GURGUR_ADMIN_TOKEN`. Do not point this branch at production Gurgur data.

`@tea/gurgur-engine` supplies Box3D physics and protocol v7. `@tea/gurgur-game` supplies the shared player/grab controllers, simulation and map compiler. Bun remains authoritative for shared bodies, players and persistence; the browser prediction worker uses the same controller code. The committed `content/generated/systems-garden.bin` is the saved-content map revision. A content test compiles the source map in memory and verifies exact binary bytes and revision against it; builds preserve the committed binary. DNS, provider setup, backups and cutover belong outside Tea.

The first port is runnable, with network and persistence tests and a browser fallback for devices without WebGPU. Full GPU browser pickup/multiplayer acceptance remains open: headless Chromium on this host loses its software WebGPU device, as it does against the source project. The original network soak remains a migration gate. Use a WebGPU-capable device for playtesting; keep the old deployment running until those gates and saved-data cutover rehearsal pass.

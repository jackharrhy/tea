# @tea/gurgur

Gurgur's authoritative Bun world, WebRTC transport, saved SQLite state and WebGPU browser. Remix 3 renders the page in `app/` and mounts the original Three renderer through a client component. The mount aborts startup work and disposes audio, workers, WebRTC, input, and rendering on navigation or failed startup. `server/src/index.ts` is the Bun entry, `web/src` owns browser gameplay, `content/` contains the authored and compiled map and media, and `tools/` contains the map compiler and diagnostic harnesses.

Install at the Tea root with `npm ci` and use Bun 1.4.4. `npm run check --workspace @tea/gurgur` typechecks, runs functional and isolated host-budget tests, builds the app, and starts the built server for readiness and shutdown; the two shared packages have independent checks. Set `DATABASE_PATH` to a new local SQLite path, `PORT` to a free port, and run `npm run dev --workspace @tea/gurgur`. The server defaults to port 3000. Production requires `ADMIN_TOKEN` of at least 16 characters and a matching `PUBLIC_ORIGIN`; WebRTC UDP uses ports 40000–40100 by default. `docker compose --profile gurgur up --build gurgur` is a local, opt-in container launch and requires `GURGUR_ADMIN_TOKEN`. Do not point this branch at production Gurgur data.

`@tea/gurgur-engine` supplies Box3D physics and protocol v7. `@tea/gurgur-game` supplies the shared player/grab controllers, simulation and map compiler. Bun remains authoritative for shared bodies, players and persistence; the browser prediction worker uses the same controller code. The committed `content/generated/systems-garden.bin` matches the currently deployed map byte for byte, including the revision stored in the live SQLite world. A content test compiles the source map in memory and verifies its binary bytes and revision; builds preserve the committed binary. DNS, provider setup, backups and cutover belong outside Tea.

The game is live from Tea, with network and persistence tests and an unsupported-device message when WebGPU is unavailable. Headless Chromium on this host can lose its software WebGPU device; use a WebGPU-capable browser for actual movement and pickup playtesting. `web/src/presentation.ts` presents the local player and locally held prop on one immediate predicted timeline, remote players and their held props on a shared buffered timeline, and loose bodies independently. Remote playback continues for at most three missing ticks and eases small late corrections over 120 ms. The `tools/network-harness/` impairment matrix and `__tests__/web/presentation.test.ts` cover packet timing; the browser playtest is still needed to judge feel.

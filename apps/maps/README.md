# @tea/maps

Maps is Tea's Remix 3 BSP viewer and early map editor. `worker.ts` delegates `/`, `/new-map`, `/editor`, and `/projects/*` to `app/controller.tsx`, passes `/api/*` and `/auth/*` to `@tea/maps-service`, forwards map room `/sync/*` requests to `@tea/maps-collaboration`, and serves built browser assets through the Worker asset binding. `cloudflare.config.ts` routes these dynamic paths to the Worker before checking static assets. The viewer uses `@tea/maps-renderer`; its example, file, folder, URL, and Hosted maps selectors are Remix client entries in `app/assets/viewer-source-panel.tsx` and `app/assets/hosted-viewer-panel.tsx`. The four viewport editor uses `@tea/maps-editor`. The Projects overview uses hydrated Remix client entries for hosted projects in `app/assets/hosted-projects.tsx` and browser-local work in `app/assets/recovered-maps.tsx`. Hosted Maps, New map, Access, and Resources tabs use Remix client entries under `app/assets/project-*.tsx` with a shared project header. The standalone New local map form uses `app/assets/new-map-setup.tsx`.

## Develop

From the repo root, run `npm ci`, `npm run check --workspace @tea/maps`, then `npm run dev --workspace @tea/maps`. The dev command builds stable browser asset names under `dist/client-dev`, watches changes, and runs `cf dev` at `http://localhost:8790`. Production builds use hashed assets under `dist/client`, so a check can run while the dev server remains open. The browser build checks that every Remix client entry has a bundle input and Worker asset mapping. The app uses the `cf` CLI and Cloudflare Vite plugin. The separate collaboration Worker keeps Wrangler for Celld compatibility.

The hosted viewer needs `@tea/maps-service` running at `http://127.0.0.1:8792` for local use. Set `TEA_MAPS_SERVICE_ORIGIN` when building or deploying the Worker for another backend origin. Set the service's `TEA_MAPS_URL` to the public Maps UI origin, locally `http://localhost:8790`, so OAuth callbacks and same origin mutation checks agree. The backend address is a trusted deployment setting. The example, local file, and remote URL modes work without the service.

Run `npm run test:hosted --workspace @tea/maps` for a browser check across the real Maps UI Worker, hosted service, and collaboration Worker. It starts disposable local OAuth, Artbin, and compiler fixtures, uses separate service and Worker data, signs in through `/auth/*`, creates a project and map, checks owner and viewer access, imports and uploads resources, opens the map in the editor, and verifies hosted build history and artifact download. The compiler fixture returns a small BSP artifact; native toolchain behavior is checked by `@tea/maps-compiler` separately. CI runs the browser flow when a Maps workspace changes. Port 8790 must be free for the Maps dev server.

For a local development fixture, put a game or mod directory under `apps/maps/local/`, with BSPs under its normal `maps/` path and assets at their normal game-relative paths. The dev server scans it on each catalog request and serves those files only during `cf dev`. This directory is Git-ignored and excluded from production browser assets. An adjacent `.tea-maps.json` sidecar can set `label`, `aliases`, and `camera`; an adjacent `.tea-maps-walkability.json` sidecar loads with the BSP. Legacy `.worldview.json` and `.worldview-walkability.json` files also load. When both names exist, Tea uses its own file. A one-map directory uses its directory name as the fixture ID, while a directory with several maps uses `<directory>/<path-without-.bsp>`. Open `/` to choose it from Local fixtures or use `?fixture=<id-or-alias>`. Do not put game files in `public/`.

To build a Steam compatibility corpus from games you own, run `npm run corpus:steam --workspace @tea/maps -- research` from the Tea root. `supported` and `all` add more games, or pass an `APP_ID[:linux|windows|macos]`. The script needs SteamCMD and `unzip`, reuses installed games when possible, and asks SteamCMD for credentials interactively. Set `MAPS_STEAM_EXTRACT_ONLY=1` to scan `apps/maps/local/steam-installs/` without SteamCMD; `MAPS_STEAM_INSTALL_ROOT`, `MAPS_STEAM_CORPUS_ROOT`, and `MAPS_STEAM_LIBRARY` override paths. The resulting manifest and compatibility report select up to three playable maps per game, exclude failed BSPs, and map extracted assets to each game's root. Raw installs are never listed as fixtures. The corpus remains ignored by Git and outside production assets. Run `npm run corpus:check --workspace @tea/maps` to recheck an existing manifest.

The same-origin `/sync/maps/:mapId/*` pass through defaults to the collaboration Worker at `http://127.0.0.1:8787`. Set `TEA_MAPS_COLLABORATION_ORIGIN` for another backend origin. It forwards room tickets and WebSocket upgrades without handling room messages. Run the collaboration Worker and service with the same `TEA_MAPS_REALTIME_TICKET_SECRET` for hosted editing. The browser stores unsent semantic operations and source-safe recovery snapshots in its own `tea-maps-collaboration` IndexedDB database.

## Viewer

Open `/` to explore generated examples without game files, open a local development fixture, select or drop a `.bsp` with accompanying assets, choose a local game or mod folder and then a map inside it, or enter a BSP URL and optional game root. The folder picker uses browser file access and preserves paths under `gfx/`, `textures/`, `env/`, `pics/`, `sprites/`, and `sound/` for local assets; it does not upload the folder. It resolves the map's referenced WADs from the folder and matches GoldSrc skybox files to the selected map's sky name. A selected BSP's adjacent `.tea-maps.json` or legacy `.worldview.json` can set its label and initial camera, and `.tea-maps-walkability.json` or legacy `.worldview-walkability.json` loads its graph. Tea sidecars take priority. Remote hosts must allow CORS. The URL form accepts palette, WAD, skybox, sprite, and sound base overrides. Existing Worldview links with a `root` parameter also load. `?example=quake` and `?bsp=<url>&gameBase=<url>` are shareable links. Generated examples were adapted from Worldview's development viewer, including the audio room. The BSP2, GoldSrc sky, sprite, and broken-audio diagnostic scenes are available with `?example=<id>` but stay out of the regular picker; local game assets are never bundled.

The Hosted maps section lists projects and successful BSP builds for signed-in members and opens private build artifacts. It supplies mounted project WADs, palettes, game-tree textures, sprites, and sounds to the renderer through authenticated resource URLs. When all six GoldSrc sky faces are mounted under `env/` or `gfx/env/`, the viewer selects the set named by the BSP.

Map tools shows format and geometry diagnostics, reports supported, partial, baked, and skipped entity classes, controls the reticle, movement mode, speed, acceleration, friction, mouse response, and field of view, exports an overview with rotation, height bounds, background, and walkability cutaway controls, generates or loads walkability sidecars with optional jump probes, and controls audio including map music tracks and volume. Overview capture and walkability generation need a loaded map and WebGPU.

Worldview's `?fixture=<id>` links open matching generated or local development fixtures. Add `camera=x,y,z,yaw,pitch` to a remote, example, or hosted build link to open at a specific view, or use Copy view link from the Camera panel. The panel also shows live position and angles. Local file and folder maps have no shareable URL.

The Camera panel is a Remix client component for reticle visibility, walk and fly mode, field of view, reset, live position and angles, and copying a shareable view link. The viewer runtime still owns camera movement and map loading.

Movement settings render through a Remix client component and update the renderer's walk and fly controls as each value changes.

The Overview panel renders through Remix. It plans export height defaults from the loaded map, validates a chosen range, and asks the renderer to capture the PNG using the selected size, lighting, rotation, cutaway, and background.

The Walkability panel renders through Remix. It generates and shows navigation graphs through the renderer, accepts JSON sidecars, and downloads Tea named sidecars.

The Audio panel renders through Remix. It follows renderer audio state, enables and mutes sound, adjusts volumes, and selects, plays, or stops map music.

Map details, entity support, and warnings render through a Remix diagnostics panel. The viewer entry applies a requested starting camera before panels read the loaded map.

## Editor

Save and Download preserve untouched local `.map` source, including comments and unsupported constructs, when the source planner can patch an edit safely. If it cannot, both stop with a diagnostic. Export normalized downloads a separate `.normalized.map` copy and never writes the opened file. Local recovery snapshots retain the semantic document and source anchors along with unapplied text edits.

Open `/editor` to create a map, load an example, add, select, duplicate, move, rotate, scale, and delete brushes with undo and redo, open a `.map` file, edit source, and save or download the result. Rotation and scaling use the center of the selected brush bounds. Selected world brushes can become a named brush entity, and selected brush entities can become structural geometry again. Add a point entity by classname and origin; select one in a viewport to edit its classname and origin, or move, duplicate, and delete it. A selected brush or point entity exposes its map properties for adding, updating, and removing keys. Tea's internal `_tb_` metadata stays outside that editor. In Chromium, Open and Save use file handles; Save checks for external changes before writing. Open project selects a folder containing `tea.maps.project.json` or the legacy `worldview.project.json`, discovers `.map` files under its configured roots, and shows a searchable project map chooser before editing one. A folder containing both manifests must be resolved before opening. It offers Save, Discard, or Cancel before replacing an edited map. It loads the project's FGD, DEF, and ENT entity definitions, follows contained FGD includes, and uses custom point classes, bounds, and default properties. It also decodes WAD2 and WAD3 packs, Quake II WAL textures, and PNG, JPEG, or TGA replacements from ordered game roots. An explicit palette takes priority over `gfx/palette.lmp` or `pics/colormap.pcx` found in game roots; later roots replace earlier textures. PNG takes priority over TGA and JPEG for the same material, while a companion WAL or base texture keeps map scale when a higher resolution image replaces it. These materials appear in viewports and Add box texture choices. Sprite roots load nested GoldSrc `.spr` files for point entity previews; the editor uses each sprite's first display frame. Incompatible or damaged resources appear under Project resource messages. Other browsers import and download copies. The editor keeps the current map and unapplied source draft in IndexedDB for reload recovery; folder handles must be selected again after reload. Local files stay in the browser. Source and numeric editing continue when WebGPU is unavailable or its device is lost; viewport tools are disabled until the page reloads with WebGPU available.

The New, Example, Open, Save, Export normalized, checkpoint, Recovery versions, and Download controls render through a Remix client component. The editor retains file-handle checks, source-preserving save plans, recovery persistence, and the Save, Discard, or Cancel guard.

The editor header shows the grid-snapped map position under the pointer in the active viewport. Its readout is a Remix client component fed by the viewport renderer.

The Save, Discard, or Cancel dialog also renders through a Remix client component. The editor continues to decide when unsaved work requires that choice and whether Save succeeded before switching maps.

The Valve map source textarea, save warning, and Apply source action render through a Remix client component. The editor still parses source, tracks unapplied drafts, persists recovery, and decides whether a source-preserving save is safe.

The Recent projects menu remembers up to 12 local project folders in this browser and the last opened map in each. Reopening a folder checks its current file permission and shows the project map chooser with the last map marked. If local storage is unavailable, Open project still works without recents.

The editor's Recent projects menu is a Remix client component. It loads stored folders when opened and hands the chosen folder to the editor's existing permission and unsaved-work flow.

Recovery versions now renders as a Remix client component. It lists local versions or hosted checkpoints, protects local versions, and asks the editor to open a detached copy through its existing Save, Discard, or Cancel guard.

Opening a local project shows its maps in a searchable Remix client component. Choosing a row hands the path to the editor's guarded map-switch flow; Project sync opens the existing sync dialog.

The project map toolbar selector and resource messages render through a Remix client component. The editor supplies discovered paths and diagnostics, and it still checks unsaved work before switching maps.

Sync project and Edit hosted source open buttons render through the same Remix client entries as their dialogs. Their bridges publish project and room availability, while the dialogs retain linking, source draft, and save behavior.

Open `/projects` to browse hosted projects and recent local project folders. A hosted project has its own `/projects/:projectId` page for maps and links to the viewer and editor. Its Open local project action checks a selected folder's game and existing hosted link, remembers the handle on this device, and opens it in the editor. Owners and editors create a map at `/projects/:projectId/new-map`; `/projects/:projectId/resources` lists member downloads and lets owners upload files, import copies from Artbin when the service is configured, and remove mounts; `/projects/:projectId/access` lets owners manage member roles. Create a hosted project from the projects page. Local folders remain on the current device; the Projects page can reopen a recent folder in the editor after checking browser permission. The editor's project controls remain available while these routes bake.

Open `/new-map` to choose the name, game, and source format for a new local map. Quake II starts with classic faces, while GoldSrc and Gower use Valve 220. The route opens a detached map in the editor; save it to a file to keep a disk copy. Replacing an unsaved editor map still requires the editor's Save, Discard, or Cancel choice.

The Shear and mirror panel transforms selected brushes and point entities without WebGPU. Shear enters a target-axis offset across the selection's source-axis span; mirror flips around the selection center snapped to the current grid. Both respect Texture lock, update point entity angles, and commit as one undo step.

Right-click a viewport to open an action menu at the pointer. It can select the brush, face, all brush faces, or a coplanar surface under the cursor; copy or paste face attributes; show the face material; act on the current selection; paste objects at the pointer; or place the currently selected point entity class at the resolved position. The menu supports arrow keys, Home, End, and Escape.

The Viewport tool offers Select and move, Face, Clip brush, Convex hull brush, Sweep faces, Vertex edit, Edge edit, Rotate, Scale, Shear, Draw shape, and Place point entity. With Select and move, drag a selected object to move it or Ctrl/Command-drag to duplicate and move it; dragging empty space draws a box. Face selects faces in a viewport; drag a face handle to extrude it, Ctrl/Command-drag to split it, or Alt-drag to translate its plane. Ctrl/Command+Alt-drag stamps a face from the perspective viewport. Face lasso selects multiple handles. The face inspector also accepts an exact distance for Extrude, Split, and Stamp, including when WebGPU is unavailable. In the perspective viewport, Alt-drag from a selected face transfers its attributes to faces under the pointer; Ctrl/Command+Alt transfers only the material, and Shift+Alt rotates the attributes. Clip brush previews a cut across selected brushes after placing two or three snapped points, or double-clicking a face to match its plane. Keep back, Split, and Keep front choose the result; Apply clip commits one undo step and hosted operation, while Reset points clears the plane. Convex hull brush places points on existing faces in the perspective viewport; Create hull commits a valid 3D point set, and its point history uses Undo and Redo until the brush is created. Sweep faces previews geometry from selected faces with a destination translation, rotation, scale, path, segment count, and iteration count. It can snap generated vertices, and the perspective viewport cap can be dragged to move, rotate, or scale the destination. Apply sweep creates all generated brushes in one undo step and hosted operation. Vertex edit and Edge edit expose handles on selected brushes for drag, snap, and surface insertion. Arrow keys nudge selected handles by one grid step; Delete removes them when the brush stays valid, and Escape clears the handle selection before leaving the tool. Rotate, Scale, and Shear show viewport handles for selected brushes and point entities. Their shared pivot starts at the selection center snapped to the grid; drag it or enter coordinates to move it without editing the map. Viewport drags preview then commit one undoable transform. The exact toolbar commands use that pivot while the matching tool is active, and Update entity angles controls angle changes on selected point entities. Draw shape uses a viewport drag to preview and create a cuboid, stairs, arch, cylinder, cone, UV spheroid, or icosphere. The shape controls set orientation, side count and circle mode, hollow thickness, sphere detail, and stair dimensions where applicable. Multi-brush shapes commit as one undo step and hosted operation. Place point entity uses the classname field and a click, with project-defined bounds affecting surface placement. Shape drawing, movement, face edits, clipping, hull creation, and sweeping preview before commit, then use the same undo history and hosted room operations as toolbar edits. Apply any source draft before a viewport gesture. Viewport tools need WebGPU; the numeric toolbar and source editor remain available without it.

View filters hide world brushes, special brush types, or chosen entity classes only in this browser session; the map source and build input stay unchanged. The Entity links panel shows all links, direct or transitive links for the current selection, or none. Both controls also work when WebGPU is unavailable, with link counts shown even if viewports cannot render.

The Issues panel reports geometry, entity, link, and structure findings from the current committed map. Filter issue types, hide findings locally, select or reveal affected objects, and apply the explicit repair offered for a finding. Reveal shows locally hidden objects and unhides containing layers; repairs use Undo and hosted semantic operations. Apply source drafts before a repair.

Layers preserve TrenchBroom-compatible metadata in the map source. The Layers panel creates and names layers, sets the active insertion layer, moves or selects objects, changes visibility and locking, marks layers to omit from BSP builds, isolates, reorders, or removes them. Removing a layer returns its objects to the default layer; the current map source retains the layer metadata for local saving and hosted collaboration.

Groups preserve TrenchBroom-compatible metadata in the map source. Select objects to create a named group, then rename, open, close, or ungroup it. A selected closed group can make a linked duplicate one grid step away; editing either opened copy synchronizes shared content until a copy is unlinked. Unlink preserves that copy as an independent group. Opening a group lets viewport tools edit its members while locking objects outside it; closing selects the whole group. Group changes use the same undo history and hosted semantic operations as other editor commands.

Constructive geometry commands operate on selected brushes: Convex merge and Intersect need at least two; Subtract uses the selection as cutters against other editable brushes and removes the cutters; Hollow replaces each selected brush with walls using the entered thickness. Each command commits as one undo step and works without WebGPU. Apply any source draft before using these commands.

Project owners can search Artbin and import a selected asset into a hosted project when the hosted service has Artbin configured. Imports copy the asset into Tea storage; assets without a stable SHA-256 or above 512 MiB cannot be imported.

The Hosted maps picker opens an authorized map snapshot from `@tea/maps-service`. Owners and editors join the live room using short-lived tickets; the current brush tools send semantic operations over WebSocket after they are persisted locally. Hosted Undo and Redo create inverse operations for this browser's edits and refuse stale inverses before queueing them. The room client reconciles pending work on reconnect and detaches expired or conflicting edits into recovery copies. A recovery copy can be reopened from the picker or the Projects page with its source anchors intact and edited as an unsaved local map. The Projects page lists copies stored on this device and links to `/editor?detachedMap=<id>`; those links work only where the copy is stored and reopen its latest local recovery revision when one exists. The editor shows other participants, their selection and pointers, and compatible preview overlays. Viewers and failed room connections remain read only. Owners and editors can open a separate hosted source dialog. It checks the latest source version and hash before replacing the room source, refuses to save while live brush edits are pending, and keeps conflicting drafts on this device for download or later retry. Source replacements are limited to 2 MiB and reconnect live room clients to the new map. The exact hosted source can also be downloaded, or the map can be turned into an independent local copy. Hosted snapshots do not overwrite the local recovery draft. The viewer can link directly to `/editor?hostedMap=<id>`; the editor asks before replacing unsaved local work and refuses to switch away from pending hosted edits until they are saved as a local copy.

The picker's Recovery copies control is a Remix client component. It reads detached copies from this browser's collaboration outbox and asks the editor to open one through its guarded map switch.

The hosted project and map picker is a Remix client component. It loads the signed-in user's projects, creates projects and maps, and offers open, compare, and local-copy actions. Opening a map still goes through the editor's guarded map switch, while the selected project is published to the access and resource panels.

The Hosted maps section shows a copyable link to the open map and lists live participants with their viewport and selection count. Remix renders this share and presence panel from the editor's room state. It counts participants only after the live room connects and shows reconnecting status if the connection drops; viewer access shows the map without claiming a live session. Recipients still need access to the hosted project.

The hosted source editor is a Remix client component. It saves a browser draft while typing and when closed, recovers that draft on reopen, and can discard, download, or submit it. Submission keeps the version and source-hash checks and waits for live edits to finish before replacing the map.

The editor's Project resources panel is a Remix client component. Project members can download mounted files; owners can upload files or a game asset folder, import an Artbin copy, and remove mounts. Changes notify the open editor so it reloads project resources.

Signed-in users can create a hosted project from the editor's Hosted maps section. Owners and editors can create a map in the selected project, optionally importing a `.map` file of at most 2 MiB. Tea checks the source syntax against the selected format before upload and opens the created map. Hosted projects currently support Quake, GoldSrc, and Gower; classic Quake map syntax is offered only for Quake projects.

Opening a hosted map now loads its mounted WADs, palette, FGD/DEF/ENT definitions, sprites, and supported texture assets into the editor. Resource diagnostics appear beside the map controls. Changes to the open project’s mounts refresh those editor resources; switching maps cancels an older load.

The Project resources panel lists authenticated resource mounts and lets members download them. Owners can upload WADs, palettes, entity definitions, and sprites, or choose a game asset folder containing supported `textures/`, `env/`, or `pics/colormap.pcx` paths. Tea checks paths and the 512 MiB per-file limit before upload. Owners can remove a mount; the service enforces the project quota and access rules.

Project owners can use Project access to find users who have signed in to Maps, grant editor or viewer access, change those roles, and remove access. The editor panel is a Remix client component backed by the same service calls as the `/projects/:projectId/access` page. Both limit visible rows and filter by name or username. The service enforces owner-only changes and protects the owner's role.

For an open hosted map, Build BSP queues a preview or final job against the server's current map version. Tea waits for the job and shows diagnostics and logs. When the service advertises an expected duration, the editor displays it beside compiler availability and while the build is queued or running. Hosted build history lists past jobs and their BSP downloads; a successful build for the current map version can open in the perspective preview. A new preview starts at the perspective camera captured when the build was requested; opening an earlier build from history uses the current camera. The hosted preview resolves the project’s current mounted companion assets through the authenticated service. Builds require owner or editor access and a configured hosted compiler. The browser waits for its queued room edits to sync before requesting a build. Local projects continue to use the separate machine-local compiler helper.

Hosted build history is a Remix client component. The editor keeps the build request, live status, and preview loading; the history panel renders builds, compiler availability, downloads, and preview actions.

With a local map open, **Compare with current source** fetches the selected hosted map and shows both sources as read-only snapshots. It includes unapplied text edits on the local side and reports the first different line and hosted version. Comparing does not save or replace either source.

The comparison dialog is a Remix client component; the editor supplies snapshots after the hosted map fetch completes.

For a folder project, **Sync project** can link local `.map` paths to maps in a hosted project. It saves the links in the opened project manifest after checking the game and each map's face syntax. Linked maps show a source comparison and whether the local file, hosted source, or both changed since the last common version. Pull replaces the local file; Push replaces the hosted source. Both directions recheck the disk file, hosted version, and source hash immediately before writing. Save or discard open editor changes first. A link from an older Worldview origin can be changed to a Tea hosted project from the same dialog. The browser stores the common sync baseline locally.

The Sync project dialog is a Remix client component. The editor hands it the current local project and guards syncing the open map; the existing sync module checks links, source revisions, and writes.

Build BSP sends the current map, project WADs, and Quake II textures used by the map to the local `@tea/maps-compiler` service at `127.0.0.1:8788`, then downloads the resulting BSP. The project manifest's build profiles select preview or final quality; without a project, both qualities are available. For an opened project, the browser remembers which compatible local compiler capability served each logical build profile. It matches the selected folder on reopening and falls back to another compatible capability when the old one disappears. The compiler's advertised game profile must match the project or hosted map. Standalone local maps default to Quake, and the Game selector can change their profile to GoldSrc, Quake II, or Gower; the choice is saved with local recovery versions. Project and hosted profiles are fixed by their metadata. Changing a standalone profile invalidates a prior build preview and export. Start the compiler with the appropriate installed toolchain before building; it is a separate, machine-local process. Build messages include compiler diagnostics and stage logs. Project resources are sent only when Build BSP is clicked. A result is discarded if the map or selected game changes while the build runs. Supported Quake, GoldSrc, Quake II, and Gower BSPs open in the perspective pane after the download; Show source and Show compiled switch views. Edits return to source and mark the compiled result stale. If preview loading fails, the BSP download remains available. The Quake II build input includes contained WAL, PNG, TGA, WAL metadata, and palette files found in ordered game roots, with later roots winning. The compiler helper enforces its configured asset count and byte limits. Export build packages the successful BSP with its referenced WADs, Quake II WALs, sprites, sounds, skybox faces, and optional source map. It snapshots available companion files after compilation, uses that snapshot for compiled preview, reports missing resources without losing the BSP download. The bundle is a ZIP when it contains more than the BSP. Export settings remember the source inclusion choice and optional automatic export per project; a selected folder replaces the same named file after checking write permission, while Downloads remain available. If automatic export cannot prepare or write the bundle, the current raw BSP is downloaded instead. Build export includes referenced Quake MDL files, GoldSrc MDL files with separate texture and sequence files, Quake II MD2 files with listed skins, and Quake II SP2 files with listed frames when those assets are available in the project. Missing companions stop the bundle export with their paths.

The export settings controls are a Remix client component. The editor supplies project-scoped settings and performs build packaging, folder selection, permission checks, and file writes. **Build & export** performs one local build and exports its bundle using the current destination and source-inclusion settings without changing the saved Export after build preference. If packaging fails, it downloads the raw BSP.

The Game and Build profile selectors, build and export actions, compiled-preview toggle, leak-path and portal overlays, engine launch, status messages, and build log are a Remix client component. The editor owns compiler requests, bundle preparation, downloads, preview loading, and diagnostic overlay state and publishes their progress to the component. A leak path appears automatically when a local build returns one; portals stay hidden until selected. Engine launch is available only when the local helper advertises a matching launch profile and the successful build still matches the open map. Hosted builds do not launch a local engine.

Local build history keeps the newest 20 results per editor document in this browser's `tea-maps-local-builds` IndexedDB database. The Remix build controls can inspect a retained result's messages and diagnostic overlays and download its BSP. History is device-local, including artifact bytes, and is separate from hosted build history. A retained result does not replace the current map source.

Local editing also keeps up to 20 automatic source versions per map identity in IndexedDB. Recovery versions lists local maps on this device; Save checkpoint creates a protected version that remains after automatic pruning. A restore opens a detached local copy with no disk file handle, so saving requires choosing a file. Existing single-draft databases are upgraded in place. The browser keeps a stable recovery identity for maps chosen from a project folder when the folder identity API is available. Reopening one of those project maps offers a newer unsaved recovery version as a detached copy. Standalone files use their name and original source fingerprint, so reopening an unchanged file finds its history; changes made outside Tea start a separate history identity.

For hosted maps, Save checkpoint records the current server map version after live edits finish syncing. Recovery versions lists that map’s hosted checkpoints for project members. Restore copy opens a checkpoint’s original source as a detached local map, leaving the hosted map unchanged.

Select all and Invert selection operate on visible, unlocked objects. Local maps can hide, isolate, or lock a selection, then show or unlock all objects; these view changes participate in undo and redo. Focus selection frames the selected object in the viewports, also available with Home. Ctrl/Command+A selects all when focus is outside an input, and Ctrl/Command+Shift+A inverts the selection. Grid nudge moves selected objects one grid step along X, Y, or Z. Duplicate, move, rotate, flip, scale, and shear commands form a repeatable sequence for the current selection; Repeat applies the sequence as one undo step, Ctrl/Command+Shift+R repeats it from the keyboard, and Clear repeat starts a new sequence.

References can load another `.map` or snapshot the current document into a read-only scene beside the working map. Each reference can be shown, hidden, offset on X/Y/Z, or removed; Clear removes them all. References are editor overlays and are not saved into map source or included in a build.

The Layers panel is a Remix client component. It displays layer membership and flags, while the editor session owns creation, ordering, visibility, locking, and source changes.

The Groups panel is a Remix client component. The editor session still owns nested grouping, linked copies, open-group selection limits, source changes, and undo.

The References panel is a Remix client component. Its scene list stays in the editor so a renderer created after a reference is added receives those overlays.

The perspective viewport has a vertical FOV control from 20° to 120°. Its default is saved in this browser, can be reset to the current default, and can be restored to the factory 60° setting. The control is unavailable while the compiled preview is showing.

The FOV control is a Remix client component. The editor applies its saved default to a new renderer and publishes camera changes to the control.

Expand switches between the four viewport layout and a perspective-only view. The dividers between viewport panes and beside the inspector support dragging or arrow keys. Tea saves the pane sizes, view mode, and camera positions per map in this browser and restores them when that map is reopened.

The Performance control samples visible-tab animation frame cadence and editor render CPU submission time only while open. It shows a bounded frame graph and can record up to 30 seconds of timing samples as copyable JSON. GPU execution time and map contents are not included.

The Performance button and panel render as Remix client components. The editor's timing collector publishes sampling updates four times per second and skips render timing when the panel is closed.

The editor header offers System, Dark, and Light themes. The choice is saved in this browser and updates the editor controls and viewport renderer; System follows operating system changes.

Selection brushes use selected structural brushes as volumes to select touching or enclosed objects, including a chosen XY, XZ, or YZ projection. The command removes the selection brushes and selects the matches in one undoable edit; Undo restores the brushes.

The Selection brushes controls render through a Remix client component. The editor still validates the selected volume and commits the query as one history operation.

The selection command buttons render through a Remix client component. Delete, duplicate, select all, invert, focus, hide, isolate, show all, lock, and unlock use the editor's same actions from the toolbar, context menu, and keyboard shortcuts.

Undo and Redo buttons render through a Remix client component. The editor still chooses local, hosted personalized, or temporary hull-point history and supplies the current action labels.

Brush and point entity creation controls render through a Remix client component, including class suggestions from project definitions. The editor still validates classnames and origins, applies definition defaults and point placement bounds, and commits entity changes through its history.

Move, grid nudge, Rotate, Scale, Shear, and Mirror controls render through a Remix client component. The editor keeps geometry validation, selection pivots, texture lock, and history transactions.

Add box, Brush texture, and Constructive geometry controls render through Remix client components. The shared brush texture still feeds shape, clip, hull, and convex merge creation; the editor retains the geometry transactions and source guard.

Clip and Convex hull tool panels render through a Remix client component. The editor still builds viewport previews, validates the geometry, and commits the resulting brushes through its history.

The face Sweep panel renders through a Remix client component, including numeric destination, path, segment, iteration, and snapping controls. The editor keeps sweep validation, viewport previews, and batch creation transactions.

The Vertex and Edge handle panel renders through a Remix client component. The editor keeps handle selection, movement, insertion, snapping, and deletion transactions.

The Draw shape panel renders through a Remix client component, including shape-specific options and visibility. The editor retains option validation, viewport previews, and brush creation transactions.

The Rotate, Scale, and Shear tool panel renders through a Remix client component, including pivot coordinates and the entity-angle option. The editor retains pivot calculation, viewport previews, and transform transactions.

The viewport context menu renders through a Remix client component, including keyboard navigation and focus handling. The editor still supplies the current actions and runs them through its existing transactions.

The Perspective Expand and Restore control renders through a Remix client component. The workspace still owns saved per-map layout, viewport visibility, resize handles, and camera restoration.

The selected point entity and entity properties inspector renders through a Remix client component. Project definitions supply choices, flags, checkboxes, and numeric fields; linked copies can keep individual properties independent. The editor still validates classnames and origins and commits property edits through its history.

The selected face picker, numeric Extrude, Split, and Stamp controls, and material application render through a Remix client component. The editor still runs those geometry and material edits through its session and source guard.

Face projection fields and Align texture controls render through Remix client components. The editor still commits projection changes and alignment as undoable edits, using project material dimensions or a manually entered texture size.

The UV editor's frame, pivot, grid, and status controls render through a Remix client component. The SVG gesture editor continues to own its view and texture transforms.

The Quake II surface inspector renders its contents, surface flags, mixed selections, unknown bits, and light value through a Remix client component. The editor still commits these attributes through its undo history.

When editing inside a linked group that has another copy, entity properties can be marked Independent in the inspector. A new protected property stays in the open copy, while edits to ordinary properties continue to synchronize. The checkbox beside an existing property can add or remove that protection.

Viewport picking treats closed groups as one selection, opens a group on activation, and expands a brush entity pick to its sibling brushes. With several brushes selected, picking a face in Face mode selects matching faces across them. Paint selection reports the resulting count in the editor status.

Face, vertex, and edge lasso gestures show a selection rectangle in each viewport. Transform gestures show their current coordinates beside the handle; these overlays stay out of pointer input and disappear when the gesture ends.

The sidebar shows a selected brush or face's material. Choose a face from a selected brush or select one in a viewport. Apply a material to the selected faces, or to every face of selected brushes. Selecting faces also exposes U/V offsets, U/V scale, and rotation; mixed values are left blank until edited. These changes use the editor's undo history and hosted room operations.

For one selected face, the UV editor shows its texture grid and face polygon. Drag the face to offset its texture, the ring to rotate, or the axis handles to scale. Drag the origin to change the transform pivot, pan with a middle or right drag, and zoom with the wheel. Grid subdivisions control snapping; Ctrl or Command bypasses it. UV drags preview in the viewport and commit through undo history and hosted room operations.

The material browser is a Remix client component that shows thumbnails for loaded project textures and generated development textures on standalone Quake and GoldSrc maps. Search, source, used-only, and usage-sort controls narrow the list. Choose a material for new brushes or apply it to the current selection; sample a selected face, select all visible faces or brushes using a material, copy its name, or replace matching uses in the current selection (the whole map when nothing is selected). The browser reports materials used by the map that are missing from the loaded sources. The editor supplies session actions and material updates through a browser event bridge.

Standalone Quake and GoldSrc maps can import WAD texture packs from the editor toolbar. Quake maps can also import a 768-byte palette. These browser-local resources are stored by map and game profile in IndexedDB, restored with the map, and included in local compiler requests and portable build bundles. Clear resources removes the current map's imported packs and palette. Project and hosted maps continue using their own resource catalogs.

The issue browser is a Remix client component. It lists geometry, entity, link, and structure findings from the editor session, supports type and hidden filters, and can select, reveal, or fix a finding through that same session.

The Document summary beside it reports revision, entity, brush, and group counts, hidden and locked objects, and geometry errors from the current editor session. It updates when the map or its view state changes.

View filters and entity link visibility are Remix client controls. They filter world and special brushes or entity classes locally without changing map source; the editor keeps the link display mode when its renderer is recreated.

The selected entity inspector shows editable properties. When a project supplies FGD or ENT definitions, it also shows suggested properties with choices, checkboxes, flag bits, and numeric controls. The raw key and value fields remain available for custom properties. Changes use the same local history or hosted semantic operations as other property edits.

Align texture supports projection reset, world axes, flips, 90° rotation, edge alignment, justification, and fitting on selected faces or brushes. Reverse direction changes alignment cycling; Subdivide when fitting uses fractions of a texture. Fit and justify use project material dimensions when available, or both manually entered dimensions for a standalone or hosted map. The alignment command is undoable.

For Quake II and Gower maps, selected faces also expose surface contents flags, rendering flags, and light value. Mixed flags show an indeterminate checkbox; unknown bits remain visible and survive edits to known flags. Other game profiles do not show these controls.

The editor can copy selected objects as portable `.map` text, paste at the last viewport pointer or at their original coordinates, and copy or paste a selected face's material and mapping attributes. Clipboard buttons keep an in-editor copy when system clipboard access is unavailable. Hosted editors with a room session can paste while online or reconnecting; the resulting semantic operation persists in the local outbox before publication. Viewers and failed room joins cannot paste. Hosted paste checks the room's edit-count and source-size limits before commit. The grid size control and Snap selection align selected brush or face vertices, and Texture lock applies to movement, rotation, scaling, snapping, and paste.

Viewport tool, grid size, and Texture lock render through a Remix client component. The editor keeps tool activation, renderer availability, and geometry operations; the component publishes the current settings to them.

Snap selection, Repeat, Clear repeat, Copy, and both Paste actions render through a Remix client component. The editor owns the transaction, repeat history, clipboard fallback, and hosted edit checks.

## Migration boundary

In browsers with the [WebMCP API](https://webmachinelearning.github.io/webmcp/), the editor registers `tea_maps_*` site tools to inspect the live document, list objects, issues, and materials, and read bounded source slices. Tools can frame the view, choose a viewport tool, select objects, faces, issues, and material uses; create a box or point entity; translate, rotate, scale, shear, duplicate, or delete a selection; apply a material; edit an entity property; and undo or redo through the same editor transactions used by the visible controls. Document edits require the ID and revision observed before the edit, reject stale calls and unapplied source drafts, and use the hosted room's personalized history when editing a hosted map. Document tools can open a map from an authorized local project folder or replace the current source as a detached copy. Opening a project map requires explicit discard confirmation for unsaved work; source replacement requires explicit destructive confirmation. Tool input is validated; unsupported browsers continue using the normal editor.

These are the first Maps slices. Worldview's remaining editor workflows and collaboration UI still need to move. The service, compiler, and collaboration runtimes have separate Tea workspaces. The original Worldview app and deployment continue running. Worldview's [MIT license](LICENSE) accompanies adapted editor behavior. See the [migration guide](../../docs/project-imports.md), [renderer guide](../../packages/maps-renderer/README.md), and [editor core guide](../../packages/maps-editor/README.md).

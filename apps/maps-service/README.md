# @tea/maps-service

This is Tea Maps' hosted-project service. It owns users, OAuth sessions, projects, maps, resources, build requests, collaboration tickets, and MCP endpoints. `src/server.ts` is the Node entry point; `src/database.ts` and `src/blob-store.ts` own local persistence. The service consumes Tea's renderer, editor, and protocol packages. It uses `data/maps` by default, port `8792`, and a separate collaboration ticket secret. The [MIT license](LICENSE) accompanies the copied source.

From the repo root, run `npm ci`, build `@tea/maps-renderer`, `@tea/maps-editor`, and `@tea/maps-protocol`, then run `npm run check --workspace @tea/maps-service`. The check typechecks, runs the service tests in `__tests__/`, and builds the Node entry point. `npm run dev --workspace @tea/maps-service` starts the local service. `GET /health` reports its status. Set `TEA_MAPS_URL` (the public Maps UI origin, default `http://localhost:8790`), `TEA_MAPS_DATA_ROOT`, `TEA_MAPS_COLLABORATION_URL`, and `TEA_MAPS_REALTIME_TICKET_SECRET` as needed. OAuth requires a compatible Fourm service with a public `tea-maps` client (the `FOURM_CLIENT_ID` default) and a registered `${TEA_MAPS_URL}/auth/callback` redirect. Set `TEA_MAPS_QUAKE_COMPILER_URL`, `TEA_MAPS_GOLDSRC_COMPILER_URL`, or `TEA_MAPS_GOWER_COMPILER_URL` to enable hosted builds for those games. `TEA_MAPS_ADDITIONAL_PUBLIC_ORIGINS` accepts a comma-separated set of extra trusted UI origins. Optional MCP token introspection uses `TEA_MAPS_FOURM_INTROSPECTION_SECRET` and `TEA_MAPS_FOURM_INTROSPECTION_CLIENT_ID` (default `tea-maps-service`). `TEA_MAPS_MCP_SCOPE` changes the required and advertised OAuth scope; it defaults to `maps:admin`. The service ignores the corresponding `WORLDVIEW_*` settings, so an original deployment’s compiler and origin settings do not leak into Tea. Host and production operations belong in the infrastructure repo.

Artbin search and import are enabled only when `TEA_MAPS_ARTBIN_URL`, `TEA_MAPS_ARTBIN_CLIENT_ID`, and `TEA_MAPS_ARTBIN_CLIENT_SECRET` are all set. Register a separate Fourm service client with `artbin:assets:read` and `artbin:assets:content` scopes for this Tea copy. The service uses those credentials only on the server and copies imported bytes into its own blob store. The original Worldview `ARTBIN_URL` and `FOURM_SERVICE_CLIENT_*` settings do not enable this integration in Tea.

Remix 3 selects all public HTTP routes through a persistent router in `src/service-routing.ts`. Controllers and HTTP helpers use Web Requests and Responses; `remix/node-fetch-server` bridges the Node listener. Large resource uploads and downloads remain streamed. The Tea Maps Worker passes `/api/*` and `/auth/*` to this service on the same browser origin. The optional static root is disabled by default because the Worker serves the UI. Do not point the service at Worldview's data directory, public origin, or existing map cells.

For a local container run, use `docker compose up --build -d maps-service` from the Tea root. This starts the separate Maps collaboration Worker on `127.0.0.1:8787` and serves the service on `127.0.0.1:8792`, matching the Maps UI's local proxy defaults. The service keeps its database and blobs in the `maps-service-data` volume; collaboration has a different volume. Both use `MAPS_REALTIME_TICKET_SECRET` from Compose. `FOURM_URL` defaults to `http://host.docker.internal:8000` in this local setup and may be set to another reachable Fourm origin. The container runs as `node`, has a health check at `/health`, and does not contain game assets or a native compiler. The local compiler remains a separate trusted-machine helper.

Compose passes the optional `TEA_MAPS_ARTBIN_*` settings from the local environment. When Artbin runs on the host, use `http://host.docker.internal:5175` for its URL rather than the browser's `localhost` address. Supply a separate Fourm service client's ID and secret with the two asset scopes described above; do not copy Worldview's client secret into Tea.

`GET /api/maps/:mapId/checkpoints` lists authoritative map-cell checkpoints for project members; editors can create one with `POST` on the same path. `GET /api/maps/:mapId/checkpoints/:checkpointId` reads its original source for members.

The MCP endpoint advertises `tea_maps_*` tools and returns Tea `/projects/:id` links from browser grants. The default Fourm token scope is `maps:admin`. Worldview tool aliases are unsupported.

Tea issues `tea_maps_session`, `tea_maps_automation`, and `tea_maps_oauth` cookies. It does not accept the original Worldview cookie names, even if the copied session rows exist in a future migration snapshot. Users sign in again on the Tea origin after a cutover.

For a hosted-data cutover rehearsal, stop writes and take consistent, separate copies of the original Worldview and Tea service data roots, including `maps.db` and `blobs/`. Run `npm run compare:data --workspace @tea/maps-service -- /path/to/worldview-copy /path/to/tea-copy --output /tmp/maps-data-comparison.json`. The read-only comparator rejects the same data root on both sides, including symlink aliases, and a shared SQLite file reached through different roots. It checks SQLite integrity and foreign keys, then compares every table's schema and row contents plus every content-addressed blob's name, size, and SHA-256. It also requires every mounted resource and retained build artifact to have its recorded blob and byte size on each side. It exits nonzero on a difference and reports table names and digests without printing row values. Run it only on stopped copies so the two snapshots represent the same write boundary. Map source and checkpoints live in the separate collaboration Celld store. Imported Artbin bytes are copied into this service's blob store and covered by the comparison; new Artbin searches and imports still need their own service configuration. Do not point the comparator at a live original data root.

`npm run test:source-cutover --workspace @tea/maps-service` is an opt-in application compatibility rehearsal. It needs the original `../worldview/apps/worldview-service` checkout built to `dist/`; use `-- --source-app /path/to/worldview-service` if it is elsewhere. The original service creates disposable users, a project, member roles, a map, uploaded resource, session, and build. After a stopped copy and exact data comparison, Tea opens the copied database and blob directory, reads the original IDs and bytes, and creates a map only in its copy. The check never opens an existing source data directory. It does not exercise OAuth callback routing or the separate Celld map-cell store.

# @tea/maps-collaboration

This Remix 3 Worker owns live map sessions, authoritative SQLite map state, operation receipts, and checkpoints. `src/routes.ts` and `src/index.ts` route authenticated HTTP and WebSocket requests to the `MapCell` Durable Object in `src/map-cell.ts`. It consumes `@tea/maps-editor/core` and `@tea/maps-protocol`; `@tea/maps-service` issues its signed access tickets. `/health` is an unauthenticated runtime check.

From the repo root, run `npm ci`, build `@tea/maps-renderer`, `@tea/maps-editor`, and `@tea/maps-protocol`, then run `npm run check --workspace @tea/maps-collaboration`. The check generates Worker types, typechecks, runs Worker and Durable Object tests in `__tests__/`, and bundles a Wrangler dry run. `npm run dev --workspace @tea/maps-collaboration` starts the local Worker. Set `TEA_MAPS_REALTIME_TICKET_SECRET` in an ignored `.dev.vars` file, using `.dev.vars.example` as a template.

The Tea Worker is named `tea-maps-collaboration`. Its `MAP_CELLS` binding has an independent SQLite migration and storage namespace. Celld reads `wrangler.jsonc`, so this workspace retains Wrangler configuration. `docker compose up --build maps-collaboration` runs it at `maps-sync.localhost` with a separate local volume and development ticket secret. The Maps app forwards same-origin `/sync/maps/:mapId/*` requests here; its editor now joins the room for semantic brush edits with a bounded, durable browser outbox. Both this Worker and `@tea/maps-service` need the same ticket secret.

For a Celld cutover rehearsal, stop writes to the original Worldview instance and make a recoverable backup of its object store. Start Tea against an **isolated copy** with `TEA_MAPS_CELLD_DEPLOY_CONFIG=wrangler.celld-cutover.jsonc`; this selects the original `worldview-collaboration-service` Worker identity and `MAP_CELLS` migration so existing map cells remain addressable. Use one Tea-specific ticket secret across the Maps service and copied collaboration runtime. The normal `wrangler.jsonc` identity remains separate. Never run this rehearsal against the original store or credentials. `CELLD_BIN=/path/to/celld npm run test:source-cutover --workspace @tea/maps-collaboration` exercises the same identity against disposable original and Tea stores; it needs the original `../worldview/apps/collaboration-service` checkout, SQLite CLI, and Celld 0.5.1-compatible binary. Pass `-- --source-app /path/to/source` if the checkout is elsewhere, or `-- --source-binary /path/to/old-celld` to verify a runtime upgrade on the copied store. The test creates a map and checkpoint in the original Worker, copies its stopped SQLite store, checks Tea's snapshot and checkpoint, then verifies a Tea edit after a crash and empty replica restore. This is fixture compatibility evidence; production transfer still needs a backup and comparison of actual map IDs and sources before routing changes.

Checkpoint metadata is listed at `GET /sync/maps/:mapId/checkpoints`. A ticketed `GET /sync/maps/:mapId/checkpoints/:checkpointId` returns its stored source for detached recovery; the endpoint does not change the live map.

For a complete read-only comparison of copied collaboration instances, use a stopped hosted-service `maps.db` copy to enumerate every map ID. Start the original and Tea Workers on separate copied Celld stores, set `MAPS_SOURCE_TICKET_SECRET` and `MAPS_TARGET_TICKET_SECRET` in the command environment, then run `npm run compare:cells --workspace @tea/maps-collaboration -- --maps-db /path/to/maps.db --source-origin http://source-host --target-origin http://tea-host --output /tmp/maps-cells.json`. The script uses short-lived viewer tickets and GET requests to compare every snapshot and checkpoint list. It checks each Tea checkpoint source against the hash in the copied checkpoint metadata. The original Worker has no checkpoint-source read endpoint, so the comparator cannot read historical checkpoint text there; keep the stopped Celld store backup as the authoritative transfer artifact. Run the hosted-service `compare:data` command on the matching service roots as a separate gate, and stop writes before taking both sets of copies. No secret or map source text is written to the report.

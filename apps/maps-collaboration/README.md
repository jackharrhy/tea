# @tea/maps-collaboration

This Remix 3 Worker owns live map sessions, authoritative SQLite map state, operation receipts, and checkpoints. `src/routes.ts` and `src/index.ts` route authenticated HTTP and WebSocket requests to the `MapCell` Durable Object in `src/map-cell.ts`. It consumes `@tea/maps-editor/core` and `@tea/maps-protocol`; `@tea/maps-service` issues its signed access tickets. `/health` is an unauthenticated runtime check. The [MIT license](LICENSE) accompanies the copied source.

From the repo root, run `npm ci`, build `@jackharrhy/tea-maps-renderer`, `@tea/maps-editor`, and `@tea/maps-protocol`, then run `npm run check --workspace @tea/maps-collaboration`. The check generates Worker types, typechecks, runs Worker and Durable Object tests in `__tests__/`, and bundles a Wrangler dry run. `npm run dev --workspace @tea/maps-collaboration` starts the local Worker. Set `TEA_MAPS_REALTIME_TICKET_SECRET` in an ignored `.dev.vars` file, using `.dev.vars.example` as a template.

The Tea Worker is named `tea-maps-collaboration`. Its `MAP_CELLS` binding has an independent SQLite migration and storage namespace. Celld reads `wrangler.jsonc`, so this workspace retains Wrangler configuration. `docker compose up --build maps-collaboration` runs it at `maps-sync.localhost` with a separate local volume and development ticket secret. The Maps app forwards same-origin `/sync/maps/:mapId/*` requests here; its editor now joins the room for semantic brush edits with a bounded, durable browser outbox. Both this Worker and `@tea/maps-service` need the same ticket secret.

The Dockerfile pins the fork's Celld 0.6.2 image by digest and accepts `--build-arg CELLD_IMAGE=<image>` for another candidate runtime. Its `dev.jackharrhy.maps-collaboration.celld-image` image label records that selection. The published image contains the same binary as the local 0.6.2 release-profile image from `ed162bf` used in a disposable container check: startup through `start-celld.sh`, ticketed map and checkpoint creation, SIGKILL, empty replica cache, and exact map source hash and checkpoint ID after restarting on the same SQLite volume. The tested local Tea image ID was `sha256:822d152224ffb90366072fbbe0c0d8e2d12814fe30e82715e68b6d211971c2f1`. No running deployment was changed.

Checkpoint metadata is listed at `GET /sync/maps/:mapId/checkpoints`. A ticketed `GET /sync/maps/:mapId/checkpoints/:checkpointId` returns its stored source for detached recovery; the endpoint does not change the live map.

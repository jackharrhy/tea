# Tea Garden

Jack Harrhy's Obsidian-backed personal site, migrated from `jackharrhy/jackharrhy.com` to native Remix 3. This is an independent Node app, not a TeaCMS site. Its routes, Markdown extensions, components, feeds, import tools, and publishing workflow belong here.

## Develop

Use the root Node version and `npm ci`. Copy `.env.example` to `.env` in this directory and set absolute paths to your external vault's `Garden` and `Assets` directories. Run `npm run garden:dev` from the Tea root and open <http://localhost:4322>. Notes are never stored in Tea. Vault edits invalidate the content index and reload the browser; code edits restart the server. Only notes explicitly marked `public: true` are served, even locally.

`server.ts` owns the Node host and development watcher. `app/routes.ts`, `app/router.tsx`, and `app/ui/` own HTTP and presentation. `app/content/` owns indexing, frontmatter, Obsidian Markdown, and publishing snapshots. `scripts/` contains publishing, asset, and Raindrop tools. `public/` holds only site-owned static assets, not vault content.

## Checks

Run `npm run check --workspace @harrhy/garden` for typecheck and fixture-based server tests, or `npm run garden:check` for shared tooling too. Run `npm run test:parity --workspace @harrhy/garden` with the original Astro site on port 4321 and Garden on port 4322 for browser comparisons. Tests and generated fixtures live in `__tests__/`; ignored local state belongs in `tmp/`.

The parity runner uses installed Chrome, captures full pages at 1440, 768, and 390 pixels, and compares readable text and pixels. It hides the live mug/iframes, stubs now-playing, and freezes GIFs at their first frame so animations do not create false differences. Override `GARDEN_BEFORE_URL` and `GARDEN_AFTER_URL` to compare staged deployments. The production rollover matched layout and text across all 30 captures, with small thumbnail/raster differences below 0.04%. The original mobile overflow on Quake and one linkblog page is intentionally preserved, not redesigned. The old implementation can be recovered from its `astro-before-tea-20261111` tag; it no longer runs from the standalone repo's main branch.

`npm run test:parity:http --workspace @harrhy/garden` additionally compares status, readable text, and links for every public note. The root dependency override pins the Markdown parser's original transitive versions: a newer CommonMark parser changes intraword emphasis in existing writing. Keep parser upgrades separate from this parity migration.

`npm run test:browser --workspace @harrhy/garden` uses isolated fixture notes to check enhanced navigation, persistent mug canvas identity, back/forward, reduced motion, forms, and the no-JavaScript fallback in Playwright Chromium. `GARDEN_PERF_URL=http://localhost:4322 node --import remix/node-tsx apps/garden/__tests__/performance.ts` from the repo root measures first/warm HTTP timings and three fresh-browser loads (FCP/LCP and transfer sizes). Compare origins from the same machine; these are lab measurements, not field Web Vitals.

The 2026-11-11 regression check used the exact original Astro image and both Garden versions on Newport, with 30 warm requests per image. Median origin TTFB was 1.8 ms (Astro), 6.8 ms (initial Garden), and 2.3 ms (prerendered Garden). Homepage transfer was 7 KB, 96 KB, and 18 KB respectively; Astro also loads its separate stylesheet. In three fresh Chrome contexts over the same SSH tunnel, median FCP/LCP was 316 ms for Astro and 336 ms for the fix. Those small browser samples include external stylesheet/font latency and do not establish a field-performance improvement. The initial public Garden request measured about 467 ms TTFB and 756 ms total; network timing is not directly comparable to loopback origin timing.

`/debug` lists public pages; `/debug/compare` compares against production (or `GARDEN_COMPARE_URL`) and stores review notes in ignored `.garden/`. `/debug/linkblog` keeps the Raindrop status and Obsidian deep links. Import commands retain their existing names; draft-writing and sync commands are explicit mutations, not part of dev startup or publishing.

## Publishing and runtime

Development reads the external vault directly. Production reads an explicit public-only snapshot at `GARDEN_CONTENT_PATH`; it never needs the personal vault. `npm run content:export --workspace @harrhy/garden` validates and writes an ignored snapshot under `tmp/published/`. Deploying application code and publishing writing are separate operations. Media keeps the existing `/asset/` URLs and production CDN at <https://garden.jack.camera>.

Production prerenders every published note before listening and retains complete HTML, Brotli, and gzip representations for the process lifetime. Queries and unknown paths cannot grow this cache; unknown pages share the 404 representation. Activating a content snapshot requires the documented restart, which rebuilds the cache. Development bypasses this cache. Feeds, Last.fm, and form endpoints remain dynamic. The Remix browser runtime enhances supported browsers' same-origin navigation; the existing canvas/viewer moves between home and header slots without resetting its spin, with native view transitions unless reduced motion is requested. Other browsers and disabled JavaScript retain ordinary document navigation.

Remix CSP protects HTML responses with a hash of the stable import map and explicit script, frame, media, and connection origins. Public HTML keeps its prerendered, compressed cache: the hash works across requests without changing cached bytes. Generated CSS and page styling currently use inline styles, so the style directive permits them; content still follows the public-only snapshot boundary.

Interactive regions use native Remix client entries in `app/ui/public/`: `Mug` owns the persistent viewer, `NowPlaying` mounts a browser-resolved frame after hydration (so live Last.fm data never enters the prerender cache), and `ToolForm` submits through a named result frame without changing the page URL. There is no HTMX dependency or global fetch/`innerHTML` swapping. Tool validation stays server-owned; forms still submit without JavaScript. The public mug model is serialized with its component props and the renderer preloads the component dependency graph, eliminating the extra model fetch and late module-discovery waterfall. `garden:mug-first-frame` marks the first rendered frame; the performance runner also instruments older versions for before/after comparison. The renderer and model fidelity are unchanged.

For the component follow-up, three fresh Chrome contexts with `GARDEN_PERF_LATENCY_MS=80` against before/after containers on the same Newport host measured median first mug draw at 955 ms before and 724 ms after. This adds 80 ms to browser requests, not to the HTTP-loop samples. The HTML grows by about 2 KB compressed to carry the model/props and preload hints, but eliminates the separate 20 KB model response. These are lab timings, not field guarantees. The document explicitly preloads the browser entry's full import graph as well as component dependencies, so `run()` itself does not become the last loading dependency.

Set `GARDEN_COMPARE_URL=https://jackharrhy.com` when exporting to compare page hashes with the deployed manifest. Export fails on missing media, conflicting routes, unknown components, or public linkblog entries without their existing required metadata. It preserves public Markdown byte for byte, refuses to overwrite a snapshot, and neither uploads nor deploys anything. The infrastructure repository's Garden guide owns confirmation, snapshot activation, restart, and rollback.

### Public asset selection

`app/content/public-assets.ts` owns the selection shared by snapshot export and asset commands. Only explicit boolean `public: true` pages authorize assets: the existing Markdown renderer handles wiki/Markdown references and raw HTML; `og-image` and the Project component's actual image/link props also contribute. HTML/SVG URLs, SVG presentation attributes (fill/stroke/filter/mask/clip-path/markers/cursor), `srcset`, styles, and CSS `url()`/`@import` dependencies are followed transitively, including relative asset-to-asset links and cycles. Explicit `/asset/…` links keep that mapping inside asset documents; other root-relative URLs address the CDN root. Query strings and fragments do not change the selected file. External origins are not fetched; `GARDEN_ASSET_ORIGIN` (default `https://garden.jack.camera`) identifies existing CDN URLs as local assets.

For intentionally public assets not referenced by pages, pass `--public-selection /path/to/approved.json` to `content:export` or an asset command. This is an explicit approval: a JSON array of asset-relative file paths, not a glob or a directory. Their transitive dependencies are selected too. Without that option, unreferenced assets remain excluded. The public deploy manifest contains only selected filenames, hashes and sizes, never an inventory of excluded assets.

`npm run assets:copy:to-r2 --workspace @harrhy/garden -- --dry-run` plans a non-deleting copy of the current public selection. Omit `--dry-run` only for an explicitly authorized upload. The command captures and hashes selected bytes, writes them into a private temporary stage with read-only files, then copies **only that stage** with checksums; it never transfers the entire vault asset directory. The stage is removed on success or failure. Export and upload are separate selections of current source: review changes before either operation.

`assets:diff` and `assets:missing:remote` compare selected filenames only; `assets:check` checks selected bytes against the remote with `--one-way`, tolerating older remote objects. `assets:sync:to-r2` is refused even with `--yes` or `--dry-run`; remote deletion is not part of this workflow. `assets:missing:local` and `assets:pull:missing` remain maintenance-only R2→local recovery, independent of public selection. Pull supports `--dry-run`, downloads missing files into private scratch with `--ignore-existing`, then creates local files exclusively without overwriting existing data. Recovery rejects unsafe remote paths and symlinks below the configured local root. It never uploads or deletes anything and never grants recovered files publication approval. Existing public objects and their URLs are not deleted or gated by the new selection; privatizing a page does not revoke an old CDN object.

Selection rejects escaping/hidden paths, non-files, missing dependencies, malformed encodings, HTML `base`/`srcdoc`, and CSS syntax it cannot safely inspect (including `image-set()`). Relative page media must use `/asset/…` or the configured CDN URL; asset documents may use relative URLs. Executable script assets (`.js`/`.mjs`/`.cjs`, or files used by a script element) require their exact path in `--public-selection`. Inline executable scripts and event handlers in asset documents similarly require that exact document's explicit approval; inline page scripts fail export with an actionable error. Inert JSON/JSON-LD script data blocks are allowed. JavaScript dependencies are not inferred or executed: explicitly approve each required dynamic dependency separately. Approval is never inherited by scripts or other documents reached transitively. Referenced HTML/SVG/CSS files are published unchanged, and public note source still includes its frontmatter; mark a note public only when its entire source is intended for publication. Tests use synthetic notes/assets and injected transfer execution, never the real vault or R2.

The local container is opt-in: set `GARDEN_VAULT_ROOT` to the external vault root and run `docker compose --profile garden up --build garden traefik` to open <http://garden.localhost>. The vault mount is read-only. Harrhy publishes `ghcr.io/jackharrhy/garden` from `main`; the image contains application code only and requires a separately mounted snapshot.

`app/ui/legacy-styles.ts` carries the deployed, minified styles as ordered Remix `css(...)` mixins, preserving rounded typography values and the responsive cascade; `public/properties.css` contains the CSS property registrations and font faces. `scripts/import-styles.mjs` records the one-time conversion, not a runtime or build dependency on Astro or Tailwind. The original bundled [picoCAD viewer](https://github.com/lucatronica/picocad-web-viewer) is retained unmodified, with upstream licenses beside it; formatting and lint skip that vendored file.

The canonical origin defaults to <https://jackharrhy.dev>; the existing `.com` and other host aliases remain infrastructure concerns. Analytics are production-only. Debug pages and Raindrop authoring tools are development-only. Host configuration, secrets, persistent snapshot transfer, and production cutover belong in the infrastructure repository. Keep the original deployment available until parity and the production smoke checks pass.

Do not rewrite Jack's vault prose. Preserve source wording and existing URL conventions during migration. Do not commit notes, media, credentials, generated manifests, or snapshots.
